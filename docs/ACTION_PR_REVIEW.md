# Pull request render review

The Breadkit Lint Action uploads SARIF or emits check annotations. It does not post an annotated image in a pull request comment. A circuit written in the Ruby DSL, or a lint configuration with `require`, can execute code on the runner. Give the lint and render job only `contents: read`; do not provide a write token or secrets to that job.

For an opt-in review link, use two workflows in the repository that owns the circuit:

1. A `pull_request` workflow checks out the proposed circuit with `persist-credentials: false`, runs the lint Action with `upload-sarif: "false"`, generates a JSON report with `bklint --format json`, and renders the circuit with `bkrender --annotations lint.json --output annotated.svg`. Upload `annotated.svg` and the JSON report with `actions/upload-artifact`. Keep the job read-only even when lint finds an error. The renderer and linter must use compatible Breadkit versions.
2. A trusted `workflow_run` workflow runs after that named PR workflow. It must not check out or execute the PR branch, run code from downloaded artifacts, or pass artifact content to a shell. Give this job only `actions: read` and `issues: write` (or the equivalent minimal comment permission). Verify that the triggering run belongs to the expected repository and workflow, was triggered by `pull_request`, and maps to an open PR in the same base repository before posting.
3. In the trusted job, use the GitHub API to find the run's annotated-image artifact and create or update one bot comment containing a link to the workflow run's artifact page. Identify the bot comment with a fixed HTML marker so reruns update it instead of posting duplicates. Treat artifact names and PR metadata as untrusted strings. The link remains useful while the artifact is retained; set an appropriate artifact retention period.

An Actions artifact downloads as a ZIP archive and its API redirect expires. It is not a durable URL that GitHub can display as an inline image in a comment. Inline images require a separate trusted, public image host and a publishing policy chosen by the adopting repository. Do not grant a write token to a job that runs circuit DSL just to make inline comments possible.

GitHub documents the [artifact handoff between `pull_request` and `workflow_run`](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run), the [risks of running PR code with privileged tokens](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target), and the [artifact download behavior](https://docs.github.com/en/rest/actions/artifacts#download-an-artifact).
